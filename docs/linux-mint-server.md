# Тихий сервер на старом MacBook: Linux Mint рядом с macOS

Для MacBook Air 11" Mid 2013 (и похожих Intel-маков 2012–2015), на которых стоит старая macOS,
а места или желания обновляться до Big Sur нет. Linux Mint Xfce ставится на свой раздел рядом с
macOS, macOS и все файлы остаются на месте. Дальше проект поднимается через Docker Compose из
репозитория, доступ из интернета даёт Tailscale.

Понадобится флешка от 4 ГБ (будет стёрта) и часа два времени. Резервная копия важных файлов
(фото) должна быть сделана до шага 2: переразметка диска — единственный по-настоящему рискованный шаг.

## 1. Флешка с Mint (на Mac)

1. Скачайте **Linux Mint 22.x Xfce Edition, 64-bit** с <https://linuxmint.com/download.php>
   (около 3 ГБ). Проверьте контрольную сумму, она указана на странице загрузки:

   ```bash
   shasum -a 256 ~/Downloads/linuxmint-*-xfce-64bit.iso
   ```

2. Вставьте флешку и найдите её номер диска. Ориентируйтесь на размер (4 ГБ) и имя:

   ```bash
   diskutil list
   ```

   Допустим, это `/dev/disk2`. **Ошибка в номере диска сотрёт внутренний диск**, поэтому проверьте
   дважды: внутренний диск обычно `disk0` и на нём видны `Macintosh HD` и `Recovery HD`.

3. Запишите образ (подставьте свой номер диска и имя файла; `rdisk` вместо `disk` ускоряет запись):

   ```bash
   diskutil unmountDisk /dev/disk2
   ```

   ```bash
   sudo dd if=~/Downloads/linuxmint-22.3-xfce-64bit.iso of=/dev/rdisk2 bs=1m
   ```

   Команда молчит 5–10 минут. В конце macOS скажет, что диск не читается, нажмите «Извлечь».

## 2. Место под Linux (на Mac)

1. Убедитесь, что FileVault выключен (Системные настройки → Защита и безопасность → FileVault):
   зашифрованный раздел так не уменьшить.
2. Отключите локальные снимки Time Machine, они мешают уменьшению раздела:

   ```bash
   sudo tmutil disablelocal
   ```

3. Дисковая утилита → слева `Macintosh HD` → кнопка «Разбить на разделы». В круговой диаграмме
   нажмите «+», новому разделу задайте размер **30 ГБ**, имя `LINUX`, формат «MS-DOS (FAT)».
   «Применить». Утилита уменьшит `Macintosh HD` на живой системе, это займёт несколько минут.
   Если она отказывает с ошибкой про нехватку места, перезагрузитесь и повторите, либо сделайте то
   же самое из режима восстановления (при включении зажать Cmd+R → Дисковая утилита).

Раздел `LINUX` нужен только как заготовка: установщик Mint его переформатирует.

## 3. Установка Mint

1. Выключите Mac, вставьте флешку, включите и сразу зажмите **Option (Alt)** до появления
   иконок дисков. Выберите оранжевую «EFI Boot». В меню флешки нажмите «Start Linux Mint».
   **Если установщик пишет «необходимо не менее 16 GB, на этом компьютере только 4.0 GB»**, Linux не
   видит внутренний SSD Apple (видит только флешку). На Air 2013–2014 это лечится параметром ядра:
   в синем меню GRUB флешки выделите «Start Linux Mint», нажмите `e`, стрелками дойдите до строки,
   начинающейся с `linux`, и перед `--` в её конце (или просто в конец строки) допишите
   ` intel_iommu=off`. Загрузка: Ctrl+X (на Mac клавиша control) или fn+F10. После этого внутренний
   диск появится, продолжайте установку как описано. Тот же параметр понадобится установленной
   системе, см. шаг 4.
2. Появится рабочий стол. Wi-Fi пока не работает, это ожидаемо (драйвер Broadcom поставим после
   установки). Запустите «Install Linux Mint».
3. Язык, раскладка. Галочку «Установить мультимедиа-кодеки» не ставьте, сети нет.
4. Тип установки: **«Другой вариант»** (Something else). В таблице найдите раздел размером около
   30 ГБ типа `fat32` (это `LINUX`; остальные не трогать: `sda1` EFI ~200 МБ, `sda2` Macintosh HD,
   `sda3` Recovery HD ~650 МБ). Выделите его → «Изменить»: использовать как «журналируемая ФС
   Ext4», «Форматировать» включить, точка монтирования `/`. Устройство для загрузчика оставьте как
   есть (весь диск `/dev/sda`). «Установить сейчас», подтвердить запись изменений.
5. Часовой пояс, затем пользователь: имя, имя компьютера, например `air`, пароль, и выберите
   **«Входить автоматически»** — иначе сервер после перезагрузки будет ждать ввода пароля.
6. Установка 15–20 минут. «Перезагрузить», вынуть флешку по запросу.

Обычно после этого Mac сам загружается в меню GRUB и дальше в Mint. Если загрузилась macOS,
назначьте загрузчик Linux по умолчанию из macOS:

```bash
sudo diskutil mount disk0s1
```

```bash
sudo bless --mount /Volumes/EFI --setBoot --file /Volumes/EFI/EFI/ubuntu/grubx64.efi
```

Вернуться в macOS в любой момент: при включении зажать Option и выбрать `Macintosh HD`.

## 4. Первый запуск Mint

0. **Если при установке понадобился `intel_iommu=off`.** Установленная система без него тоже не
   увидит диск и остановится на `initramfs`. При первой загрузке в меню GRUB (если оно не показалось,
   держите Shift или нажимайте Esc сразу после включения) выделите Linux Mint, нажмите `e`, в строке
   `linux` после `quiet splash` допишите ` intel_iommu=off`, Ctrl+X. После входа закрепите параметр
   навсегда:

   ```bash
   sudo sed -i 's/^GRUB_CMDLINE_LINUX_DEFAULT="\(.*\)"/GRUB_CMDLINE_LINUX_DEFAULT="\1 intel_iommu=off"/' /etc/default/grub && sudo update-grub
   ```

1. **Wi-Fi.** Меню → «Менеджер драйверов». Без сети он предложит вставить установочный носитель:
   вставьте ту же флешку, выберите `bcmwl-kernel-source` (Broadcom 802.11 Linux STA wireless
   driver), «Применить изменения», перезагрузитесь. В трее появится Wi-Fi, подключитесь.
   Запасной путь, если менеджер не справился: раздайте интернет с телефона по USB-кабелю
   (Android: «USB-модем») и выполните `sudo apt install bcmwl-kernel-source`.
2. Обновления:

   ```bash
   sudo apt update && sudo apt upgrade -y
   ```

3. **Не спать с закрытой крышкой.** Настройки → «Менеджер питания»: на вкладках «От сети» и
   «От батареи» для «При закрытии крышки» выберите «Выключить дисплей», а «Переводить систему в
   спящий режим» — «Никогда». И на всякий случай запретите сон на уровне системы:

   ```bash
   sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
   ```

   ```bash
   sudo sed -i 's/^#\?HandleLidSwitch=.*/HandleLidSwitch=ignore/; s/^#\?HandleLidSwitchExternalPower=.*/HandleLidSwitchExternalPower=ignore/' /etc/systemd/logind.conf && sudo systemctl restart systemd-logind
   ```

4. Удалённый доступ по сети для управления с основного компьютера:

   ```bash
   sudo apt install -y openssh-server
   ```

   Теперь `ssh имя@air.local` работает из домашней сети.

## 5. Проект через Docker

```bash
sudo apt install -y docker.io docker-compose-v2 git && sudo usermod -aG docker $USER
```

Выйдите из системы и войдите снова (или перезагрузитесь), чтобы группа `docker` применилась. Затем:

```bash
git clone https://github.com/vbuleiko/myciti.git ~/myciti && cd ~/myciti
```

(пока нужная ветка не слита в `main`, добавьте `-b имя-ветки` после `clone`)

```bash
docker compose up -d --build
```

Сборка на этом процессоре идёт 5–10 минут. Проверка:

```bash
curl -s http://127.0.0.1:8080/api/health | head -c 300
```

Карта открывается с любого устройства дома по адресу `http://air.local:8080`. Контейнеры помечены
`restart: unless-stopped`, после перезагрузки ноутбука они поднимаются сами. Настройки, как обычно,
в `~/myciti/.env` (образец `.env.example`); после изменения `.env` или `git pull` повторите
`docker compose up -d --build`.

## 6. Доступ из интернета: Tailscale

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

```bash
sudo tailscale up
```

Команда напечатает ссылку: откройте её на телефоне и войдите (Google, Apple, Microsoft или GitHub).
Бесплатного тарифа хватает.

**Только для себя.** Поставьте приложение Tailscale на телефон и ноутбук и войдите в тот же аккаунт.
Карта доступна из любой сети по адресу `http://air:8080`, снаружи её не видно, ничего больше
настраивать не нужно.

**Публичная ссылка** (чтобы дать кому-то ещё):

```bash
sudo tailscale funnel --bg 8080
```

В первый раз команда попросит включить Funnel по ссылке в консоли Tailscale, после этого выдаст
постоянный адрес вида `https://air.имя-сети.ts.net`. Он не меняется при перезагрузках. Наружу
смотрит только nginx проекта с его ограничениями, API только для чтения.

## 7. Данные

История пишется внутрь тома Docker. Забрать её на основной компьютер (команда на основном
компьютере, при включённом Tailscale или из домашней сети):

```bash
ssh имя@air 'sudo tar czf - -C /var/lib/docker/volumes/myciti-data/_data observations' > observations.tgz
```

Распакуйте и смотрите сводку из репозитория на основном компьютере:

```bash
tar xzf observations.tgz && pnpm observations -- summary --dir ./observations
```

## Необязательно: отключить рабочий стол

После настройки графика не нужна, без неё свободнее память:

```bash
sudo systemctl set-default multi-user.target
```

Вернуть: `sudo systemctl set-default graphical.target`. Всё управление дальше по `ssh`.

## Если что-то не так

- Mac не показывает «EFI Boot» при зажатом Option: флешка записана неверно, повторите `dd`,
  проверив номер диска и что образ скачан полностью (контрольная сумма).
- В установщике нет раздела 30 ГБ: шаг 2 не применился, вернитесь в macOS и проверьте в Дисковой
  утилите.
- После установки загружается только macOS: команда `bless` из шага 3.
- Wi-Fi не появился после драйвера: `sudo dkms status` покажет, собрался ли модуль `bcmwl`; если
  нет, обновите систему через USB-модем телефона и повторите установку драйвера.
- `docker compose` ругается на права: вы не перезашли после добавления в группу `docker`.
- Ноутбук всё же засыпает: `systemctl status sleep.target` должен показывать `masked`.
